# RAG_all 纵向实施切片与前置门槛

目的：使开发者可按已记录行为逐步实现和验收，不把“需求定稿”误当“所有能力已验证”。范围与唯一验收基线是 [PRD](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/prd.md)，跨模块政策见 [实施契约](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/ir-review-2026-10-15/implementation-contract.md)。这是可拆成故事的实施单元，不是已运行冲刺或已完成代码；不生成虚构 sprint-status。

本文件已按第二轮独立 IR 修正实施依赖；最终定点复核和发现状态以 [本轮报告](/E:/aaa-project/rag/_bmad-output/planning-artifacts/implementation-readiness.md)为准。P0 和每个切片的账号／环境／真实能力验证条件仍须执行，不能将规划状态当作这些条件已通过。

## 先后关系

S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7。P0 在 S0 的适配器、调用意图／派发守卫／成本账和限制骨架可用、真实凭证具备后尽早开展，可与 S1 并行；不等全部业务页面做完才第一次测格式、图意或资源。P0 是隔离样例探路，不向业务用户开放未完成鉴权的入口。

**F0：首次调优前冻结。** AI 先备资料和独立开发题；在任何以结果选择参数的调优前，冻结32条验收题、资料版本、原金标证据单元与判定规则，保存时间／hash及受控访问记录。开发题与验收题隔离。若S7之前开始调优，F0必须前移；若此前一直未调优，可在S7首个子步骤冻结，再优化和验收。不要求S0前固定32题，也不把普通功能实现一概称作调优。若P0图意探路题会被用于调优，则它属于开发资料，不能再伪装未暴露验收题；真实来源变更保留旧版并按PRD记录污染／另备留出验证，不删失败题或改变门槛。

## S0：可重建的工程基础和隔离适配器

- **前置：** 已记录的 PRD 与实施契约；无需外部模型账号即可开始。
- **交付：** 模块化应用／worker 骨架、配置与秘密注入、依赖／镜像锁定、真实 PG＋pgvector 的迁移、短 Session、统一错误与 request_id／operation_id 结构；独立持久epoch与DB一致性守卫；MinerU、embedding、问答和可选图意适配器及可控假件。先交付所有外部调用共用的持久intent、派发检查、超时unknown和迟到成本幂等回填；资产清单/attempt隔离目录、磁盘预算与维护恢复骨架。epoch初始化不冒称已完成可信恢复演练。
- **验收：** 干净环境可启动／迁移／停止；配置/epoch矛盾可识别且隔离；假件明确模拟成功、超时、未知与非法结果，不能标成真实服务通过；意图提交前／后、可能发出后崩溃与业务终态后usage回填有真实PG负例，旧执行者不能借回填提交业务；日志无凭据或私有正文。
- **任何真实外发前的 rate gate：** 交付 [C8 共享限流](/E:/aaa-project/rag/_bmad-output/planning-artifacts/architecture/architecture-RAG_all-2026-10-16/shared-contracts.md:145) 与 [R2 受监督派发](/E:/aaa-project/rag/_bmad-output/planning-artifacts/architecture/architecture-RAG_all-2026-10-16/runtime-operations.md:23)；真实 PG＋可控传输假件覆盖 grant 后暂停跨秒／分钟、检查后暂停、另一槽推进、失联 child、重复 seal／重启。断言领取窗口过期仍保留 open charge、未证明全部停发不退占、该 call 发送 child／后代退出、全部发送 FD／IPC 关闭及旧 grant 销毁的监督证明后取得 DB 上界并保留完整 W、准入同时计 open＋sealed 未满 W；禁止只靠 child 读钟／lease／send-by。失败须阻断对应外发，不延后至 P0 才补本地算法。
- **出处：** NFR-3／5／6、FR-4／15／16；本阶段不宣称 SM-1–SM-7 全通过。
- **失败处理：** 迁移或配置失败先定位修复，不跳过为 SQLite 的通过结果来替代 PG 事务与向量行为。

## P0：真实外部能力与目标资源探路

- **前置：** S0 适配器／调用记录及上述本地 rate gate 假件负例全部通过；可用账号与合法样例。实际调用前取得运行侧凭据，按已确认的 API 方向执行，不把开发工具账号当运行服务。
- **交付：** 固定原件版本与 hash 的 PDF／DOCX／TXT／MD 样例，规则及简单跨页表格、扫描页、必须理解图中连接关系的题；实际 MinerU 响应／ZIP、来源映射、embedding 配置／维度与问答结构，必要时独立视觉 API 的实际结果。独立用途profile的输入/输出/总token、完整消息计数依据、非思考普通文本JSON模式/compact档/完整输出预留与实际可受理形状、RPS/TPM/响应字节和SDK禁暗重试须登记；未证模式不生成，不从OpenSearch计数接口推定DashScope可用能力。
- **验收：** 文本、表头行列、数值单位、页／结构引用可回查；图意题必须有直接依据，图注或仅识字不算通过。首个可用生成profile证明四场景最小完整有效载荷有空间，最大输入/24格仅通过预算的组合才受理；验证高token输入、输出上界/length/非法JSON、计数偏差失效、零候选不需LLM与非零未证失败分支。实际调用状态、用量／费用或未知及失败记录完整。目标 4C4GB 主机接通后测服务并存 RSS、连接、磁盘、超时；开发电脑结果不替代生产资源结果。
- **真实限流核验：** 按已核账号／用途／总池限制取有效有限上限，检查实际 SDK 无暗重试、每 call 经过 C8、open／sealed charge 与停发证明账可核对；分别保留本地发送时间与可得远端响应／429，不把本地窗口证明当远端到达或永无 429 保证。文档任务的两个 gate 各默认4、可配1–4、所有账号合计最多4，本机重处理槽仍1，原 job deadline 不刷新；P0 分别核池1和4的公平 poll、unknown／恢复及并存资源。
- **缺口分支：** MinerU 图意不足仅触发图意 API 验证，保留 MinerU 主路和绑定来源；定位不足先修适配／回退，不猜位置。仍达不到 FR-7 则阻断 S5／整期完成，不能降验收或假称图意已支持。资源不足先限制并发、流式与输入上限再测；仍不能满足记录真实变更提案。
- **边界：** 账号／环境暂缺时可继续 S0／S1 的独立工作，不能以假件成绩替代 P0；S2 的真实格式接通须通过对应解析与来源检查，S5 须通过图意分支。

- **验收：** FR-1–FR-5 的角色／转让／撤权反例；双凭据、混合越界目标整体拒绝；无权与不存在目标不泄露存在性。并发争最后一笔原件／次数预留仅一笔成功；无效同键、异内容、过期和崩溃回收按契约。
- **登录与私有响应交付／验收：** 匿名登录按 [C5](/E:/aaa-project/rag/_bmad-output/planning-artifacts/architecture/architecture-RAG_all-2026-10-16/shared-contracts.md:79) 接受无 Cookie／无会话 token 的精确同源 Origin＋JSON＋`X-RAG-Login: 1`，成功旋转会话／绑定 CSRF token 并经不缓存登录响应交前端内存，重载可经同源当前认证的 no-store context GET 取本会话 token；拒 missing／null／跨源 Origin、简单 form／缺固定头，CORS 关闭。已认证 Web 写继续 Origin＋会话 token。按 [C2](/E:/aaa-project/rag/_bmad-output/planning-artifacts/architecture/architecture-RAG_all-2026-10-16/shared-contracts.md:20)／[R4](/E:/aaa-project/rag/_bmad-output/planning-artifacts/architecture/architecture-RAG_all-2026-10-16/runtime-operations.md:51) 交付所有私有响应含错误／认证／状态的 no-store 与网关禁缓存，首版不发验证器或304；If-*仍完整授权。真实浏览器验证同 URL 换账号／撤权、history／bfcache：pagehide清私有DOM，pageshow先遮蔽清context／代次，当前context及全部依赖重核后才显示；不持久缓存私有内容。
- **出处：** FR-1–FR-5、NFR-1／2／6、SM-6 的对应基础用例。

- **失败处理：** 不因恢复能打开旧引用就放行；未知安全事实保持隔离。异维迁移失败保留可恢复旧存储，不自动改 DDL 或混查。

## S7：固定验收、优化比较与工程证据

- **前置：** S6；四场景开发检查完成，环境／资料／模型／分块／检索与合并配置已固定。
- **交付：** 使用F0已冻结的题目／金标来源／必要证据单元／口径；开发题上提出优化并锁方案；相同冻结题与条件下保留 B0、上一保留轮和本轮的完整原始输出、权限／故障／恢复结果、资源和实际费用。补 API／部署文档、一次真实异常复盘和用户理解材料。不得到本片才根据已见结果挑选“可过”的32题。
- **验收：** SM-1–SM-7 全部按 PRD 判断；权限独立全通过，关键表格／OCR／图意／冲突／版本题不能由其他得分抵消。首次资源／成本基线后、优化比较前登记绝对目标，少量样本不包装泛化或捏造 P95。
- **防泄漏：** 调优只据开发题，不用冻结题逐题反馈选参数；冻结配置、原始题目和全部结果留档。若题目暴露，记录污染并另备留出验证，不删失败／改分母。优化无收益／退步仍保留，不预填提升百分比。
- **出处：** FR-1–FR-16、NFR-1–NFR-6、SM-1–SM-7、PRD 第 8.2–8.4 节。
- **失败处理：** 未达标报告差距并继续修复或按真实证据提出变更，不以切片已完成替代整期完成；AI 做过与用户能解释的范围分别记录。

## 开始与完成的不同门槛

IR 的“可开始实施”只要求上述政策、前后依赖、受理／状态／结果和验证路径已经明确。实际 P0、部署、数据质量或资源尚未运行，不是可省略的检查；它们是明确的执行停止点。S0 可在当前记录基础上独立启动，后续切片须满足所列前置条件，最终完成必须全部验收通过。
