# M2 · 重建与最小页面动作契约

以下为受托 TS 决定，不声称上游已经实现。普通资料自动程序校核，无逐份人工发布审批。Web 展示与后端状态分开，前端禁用按钮不代替服务端守卫。

第二轮现行补充：所有私有页面从S1起使用账号/登录实例/空间/epoch响应归属，S2即交付最小校核回看；未PUT候选可经候选GET/abandon查看/放弃并有限过期。已fence终态的清理余账占容量/物理预算，但不再算有发布资格的写意图永久挡guard。过期任务的“继续核对”是新有界只读reconciliation，不能续活旧job/下载发布；真正本地继续须另显式新job及当前guard/预算。任务状态GET与维护动作分开，降级仍有库读权者保留本人受控状态只读。详细现行状态、接口和停止/清理屏障以[实施契约第2.4–2.7及5.1/5.5节](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/ir-review-2026-10-15/implementation-contract.md)为准，不从旧表概括词放宽这些条件。

## embedding、存储与切换

1. 每 KB 以 active_index_generation 指向生效索引代；不可变的是 generation 身份、embedding_profile_id、chunk_config_id、vector_store_id 与初始发布快照，不能把这一表述解释成库内文档永远不得变化。正常导入／替换在同活动 profile 下准备新块／向量，短事务锁 KB 复核守卫后原子发布块／向量可见性与文档 active_version、递增 docset_revision；新查询按该 revision 的活动文档集检索，不要求每份上传全库重建，也不回写初始发布快照。块／向量行及历史来源不可原地改内容。profile 固定 provider、端点／地域、model、可观察版本、维度、query/document 处理与前缀规则、L2 归一化、cosine metric。密钥引用与可轮换凭据独立，不因仅换凭据重建。供应商 alias 不暴露权重版本时，保留实际 model／request_id／时间和不可完全复现的限制，不假称完全冻结权重。
2. 平台默认配置只影响新库或显式发起的重建，不原地改已有 profile。请求在执行快照中固定各库 generation／profile／文档版本；profile 的向量空间兼容指纹必须相同，任一不兼容则整请求拒绝，并提示需统一索引。比较的是规范字段兼容指纹，不只比较模型名，也不要求不同 KB 的 profile_id 字面相同。旧执行和重放遵循 M1 原快照及当前重新授权／墓碑守卫。
3. 首版部署只批准一个维度 D，由首个实际接入并验证的 embedding 配置锁定，PG 存储为经迁移创建的 vector(D)。同 D 的模型／处理变更可走本节在线候选重建；不同 D 的重建准入拒绝 EMBEDDING_DIMENSION_MIGRATION_REQUIRED。变维须计划维护窗口、备份与显式 Alembic 迁移，按目标 D2 建隔离新存储及维度约束，保留旧存储供失败退回；按完整迁移流程重建全部受影响库、切换并验证授权／删除／引用／查询与失败退回，成功后才退役旧存储。维护期间停止受影响查询／写入，删除请求可登记墓碑并在恢复前重放。应用不动态 DDL，首版不承诺任意维度在线双索引或无停机切换，不在文档中猜 D。
4. 同维重建开始时，短事务锁 KB，若已有上传／替换／重处理写意图尚未终结，整次重建拒绝 KB_WRITE_IN_PROGRESS；未终结包括已持久但未发布／取消／废弃的候选、上传在途及原件容量预留、排队／运行／待核对任务，不只看 worker running。失败但仍可重试的候选须先显式取消／废弃才不再阻挡。新上传／替换的原件容量预留与写意图登记，也在同 KB 短锁事务中先检查 guard、再原子登记；字节传输在事务外进行，重建能看见其持久预留。因此两入口按同一锁竞争，不留下重建漏查的在途写。若没有未终结写意图，才创建候选 generation、记录 docset_revision 和全部 active 文档版本，取得有 owner_job／attempt／guard_token／lease_until 的持久写 guard，再提交任务。沿用单文档 worker 与独立心跳，不增加并行常驻 worker。
5. guard 记录存在期间，上传／替换／重处理均在预留原件容量前整拒 409 KB_REBUILD_IN_PROGRESS（页面显示原因与可重试入口），不排隐形队列、不产生孤儿容量预留；过期未回收也先拒绝并唤起恢复器，不由前端或单纯时间判断放行。旧索引继续查询，引用／授权管理照常。删除仍允许：同一事务先落 tombstone、递增 docset_revision、使候选 invalid，并按锁内读到的 guard 所属 job／attempt／token 立即条件释放；远端取消尽力而为，不能等待远端才挡访问或解锁。旧索引虽仍有被删文档行，查询先在数据库过滤当前墓碑、返回前再检查，不能等重建取消或物理清理。库／空间删除也遵循父级墓碑，不允许复活。
6. 重建终态失败、用户取消或租约过期时，任务恢复器通过 KB／owner_job／attempt／guard_token 条件更新标记候选废弃并释放 guard；应用重启后同一恢复器清理过期记录。**所有解锁都使用该完整条件，匹配失败只作无操作；旧 attempt 不得释放后来新任务的 guard。** 后续新重建取得新 attempt／新快照；旧 attempt 不可重新心跳续活或发布。候选物理清理可异步，清理未成不维持写 guard，也不恢复访问。
7. 发布短事务重新锁 KB，必须同时验证：当前有效 job／attempt／未过期 lease；guard 仍归该 attempt；候选完整 ready；无父级／文档墓碑；docset_revision 和覆盖的 active 文档版本集与快照逐一相同；向量数量、维度和 profile 校验通过。仅通过才原子改指针并解 guard；任一不符废弃候选、解本 attempt 的 guard，旧索引仍生效。不同库逐库完成，不做全平台双写；A 切完而 B 未切时若 profile 不兼容，A+B 查询整拒，单库可用。提交前删除与切换竞争由同 KB 锁及 revision 守卫排序。

“索引代完整”指完整覆盖快照中已发布、通过校核的规范化来源范围；若同时改 chunk_config，可从同一不可变来源范围生成新块，不改变来源身份。生效文档若是合法首次 partial，重建不得把它改标完整、加入未通过范围或顺便切换文档候选。索引代指针与文档 active_version 是两个独立守卫；本次只改索引指针。解析参数变化须另走文档候选，不借索引重建修改解析历史。

切代后的新请求使用新代；原在途问答保留原 generation／文档版本／块快照运行至终态或其受理时固化 deadline，超过 deadline 终止失败，迟到结果不能发布，不把旧检索暗换成新查询。旧代向量与执行所需块要保留到引用该代的全部在途操作终结或各自 deadline 到期，才允许回收；返回仍重新授权并检查墓碑。历史引用所需的原件、准确片段及定位按既有保留规则保留，不随向量回收改写。旧代与候选实际占盘纳入内部预算／磁盘水位保护；资源不足暂停新接收／重建，不能提前删除仍被有效操作引用的数据或假定旧向量不占磁盘。

## 页面状态／动作矩阵

页面固定分栏显示“当前生效版本／候选版本／本次任务”，各有版本号／任务号与错误、失败范围；索引重建另显示生效 generation 和目标 profile。没有候选写“无候选”，不能把旧版状态覆盖成笼统的“处理中”。

| 状态 | 使用者看到／可做 | 有库维护权者另可做 | 后端约束 |
|---|---|---|---|
| 首次导入排队／处理中，无生效版 | 明示暂不可查询；看文档处理状态 | 看原件、进度／错误；取消 | 候选不检索 |
| 首次完整通过 | 当前版本就绪，查询／引用 | 查看校核产物；替换 | 程序校核后自动发布，无人工批准按钮 |
| 首次部分可用 | 查询仅用通过且可定位范围，持续显示不完整及失败范围 | 对照原件与提取／结构差异；重试或修订重交 | 发布边界沿用 Q2，不以 partial 冒充完整 |
| 旧版生效，替换候选处理／部分失败 | 旧版仍可查询；候选不混入新答案 | 看候选原件与提取／结构差异、失败页／块；重试、取消或修订重交 | 完整 ready 才自动切换；不完整替换不覆盖旧版 |
| 外部结果未知／待核对 | 旧版可用性独立显示 | “继续核对”先查原 batch／任务；无法确认时显示未知状态、潜在重复费用后允许显式“知情重交” | 不自动重复付费提交；保留原关联／attempt，迟到成果受守卫 |
| 同维索引重建中 | 旧 generation 可查询；显示目标与进度 | 取消、看失败详情；仍可删除 | 上传／替换／重处理整拒；删除使候选失效并解 guard |
| 重建失败／取消／过期 | 旧 generation 仍可用，明确失败原因 | 重建入口恢复可用 | guard 已释放，旧 attempt 不可切换 |
| 已删除／撤权 | 隐藏受保护内容；引用显示删除或无权 | 仅当前有权维护者可看清理状态 | 原件／产物／图像／下载全部重授权；清理失败不解禁 |

“修正”首版只包括修订原件重新上传，以及允许的元信息／解析参数变更后生成新候选。解析失败重试可复用候选身份但须新 attempt；改变内容、模型适用版本或解析参数不能原地改旧产物。对照页提供原件与提取内容明确标签、结构路径／页、表格图像及错误范围；不内建通用富文本／OCR 编辑器，不原地重写历史引用。权限／标题等纯管理操作仍须授权，不可借元信息接口修改已冻结来源内容。

## 引用回看

| 来源 | 最小行为 |
|---|---|
| PDF，有已验证 bbox | 后端解析 citation ID 到不可变版本和 1 起物理页；页预览并高亮实际 bbox，显示准确提取片段、页号及图表号；校验坐标范围与上游页基数 |
| PDF，无 bbox 但有可靠页 | 打开该物理页，显示位置提示／图表号和准确提取片段；标“无区域高亮”，不伪造坐标 |
| DOCX／TXT／MD | 展示实际章节／结构路径、段落或字符范围及准确提取片段；提供当前授权后的原件下载。标明“提取片段”与“原件”；DOCX 不伪造物理页，不部署 Word 服务 |
| 定位失败／哈希不符／资源缺失 | 明示定位不可用，不跳猜测页；仍有权且原件存在时可下载核对。缺必需定位的候选不能假装通过发布／验收；历史资源损坏须记录故障 |

所有引用、页图、提取产物和单文件下载均重新授权并检查版本归属／tombstone。仅向调用者返回受控端点，不直接信任模型 URL 或上游临时地址。切版不改历史来源映射；删除立即禁止旧引用访问。
