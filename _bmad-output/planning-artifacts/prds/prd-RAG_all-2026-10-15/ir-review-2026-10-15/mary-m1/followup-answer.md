# M1 收口

接受三项追问，以下补充优先于主答复中可能含糊的表述；仅复用已有证据，属于本项目 TS 决定。

1. 选 API 启动时扫描一次、其后周期扫描 PG 的轻维护协程，不新增服务；单次扫描短事务、可被多实例安全竞争领取。生成操作保存 hard_deadline、lease_until、claim_token、attempt；续租不得超过 hard_deadline。恢复器在 lease 到期或硬期限到达后，按原代次条件终止并释放一次。完成提交须同时满足 running、期限未到、lease 有效、token/attempt 匹配，结果/依赖/结算同事务；旧执行者和迟到结果不能成功。跨日失败同 Key 只回原失败，不重新预留或调用；新 Key 才按新受理日建立新操作。
2. 执行问答/对比能力前预留；零候选由确定性模板返回合规完整不足答复，即便跳过 LLM 仍计 1，纯检索零结果不扣问答。成功以校核、当前权限检查通过后，结果＋依赖＋计次原子提交为界；HTTP 回包丢失或之后断网不撤销成功，客户端可同 Key 重放。真正业务超时、依赖/校验/输出许可检查失败才释放。成功后撤权或删除来源，重放拒绝，原成功计次不回滚；不承诺网络发送与并发撤权全局原子。不得把“客户端没收到”自动改成业务失败并另发付费调用。
3. Web 每文件先以 operation_id 建候选并预留，再向该候选上传；重传沿用 operation_id/候选，禁止自动新建版本。上传中逐段核对实际字节与声明/预留，未知长度先占单文件上限；读超立即中止，临时资产清完才释放。同候选完成后同 hash 回已有结果，异 hash 返回 409；未完成重传先 fence 旧上传 attempt、清其临时资产，再复用候选。批量逐文件独立返回。HMAC 元数据保存 key_id；旧校验键保留到对应 Key/墓碑有效期结束，不匹配返回冲突，缺键视为可识别服务配置失败，均不当成新提交。

本题闭环；实现验收沿用主答复五项故障用例，并注入“完成提交后丢回包”和“旧 attempt 迟到”。
