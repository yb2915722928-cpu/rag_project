## 已核对一致的边界

1. **所有权与知识库负责人分别判定。** 所有权转让后，原所有者成为维护者，失去所有者固有全库范围，保留原有逐库授权及负责库权限；原所有者随后退出、被移除或降为使用者时，其负责库再由现任所有者接管。不能把“转让团队”直接解释为“转让全部知识库负责人”。依据：[FR-2](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/prd.md:111)。
2. **所有者全库范围是明确例外。** 其他成员依逐库授权或负责库身份访问；加入团队不自动获得全部资料。平台管理员不因建立团队而获得资料读取权。依据：[角色表](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/prd.md:87)。
3. **只读程序 API 与 Web 管理流程不冲突。** 对外程序凭证只读，不意味着 Web 背后的管理入口不能执行角色允许的写入。本人导入任务状态同样必须受凭证单一空间、指定知识库与用户当前权限交集限制，不能只验证任务创建者身份。该限制是 FR-5 与 NFR-1 的统一授权规则在任务状态上的应用。依据：[FR-5](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/prd.md:141)。
4. **撤权覆盖已保存内容。** 历史回答、引用、下载及追问上下文均重新鉴权；允许整体隐藏受影响回答，避免要求实现细粒度正文重写。完整答案在检索时与返回前复核，首版不要求流式输出。依据：[FR-14](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/prd.md:211)。
5. **平台身份与本人身份可并存。** 平台管理员可以作为普通用户访问本人个人空间，不能借平台身份读取他人个人空间；另具有效团队身份时按团队权限访问。资料正文、历史和评估原始记录属于受控业务数据，不能借运行日志入口绕过授权。依据：[FR-4](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/prd.md:133)、[FR-16](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/prd.md:227)。

## 首次发现与精确规则历史

### P1（已处理）：撤销负责人的访问时，应同步移除负责人身份

首次校验时：[角色表](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/prd.md:87)给予维护者负责库访问和授权管理能力，FR-3 又要求撤销后立即失权；当时未明确撤销负责人的访问时如何处置该隐含权限。如果只删除普通授权，负责人仍能以负责身份访问或自行重新授权。该缺口现已按上述定点复核结果补齐。

Mary 受用户委托确认的最小闭合规则：**团队所有者撤销某负责人的该库访问时，必须同步接管该库负责人，并移除该成员对该库的全部授权。普通负责人不能自行恢复负责人身份或重新获得该库权限。所有者固有全库范围不能通过普通库授权操作撤销，须通过所有权转让及后续成员操作改变。** 这不新增向任意成员委派负责人的功能。

验收：维护者创建库后，所有者执行该库撤权；原创建者通过 Web、程序凭证、引用、历史及授权管理入口均不能访问该库，现任所有者仍可管理，其他不受影响成员的授权保留。

### P2（已处理）：所有权转让目标应限定为团队内已有的有效成员

首次校验时：FR-2 保留了交接要求，但遗漏 Mary 原方案中“向一名现有有效成员转让”的目标约束。若允许任意注册账号接任，会绕过接受邀请后才能成为成员的规则。该缺口现已按上述定点复核结果补齐。

Mary 受用户委托确认的精确规则：**所有者转让和平台办理的所有者变更，目标均须是本团队已加入且有效的成员；非成员先完成邀请加入。成功变更后仅保留一名有效所有者。** 初次创建团队时指定初始所有者仍是已定义的初始化例外。

验收：对未加入、未接受邀请、已退出或已停用账号转让失败；向有效维护者或使用者转让成功，双方角色及有效权限随之更新。
