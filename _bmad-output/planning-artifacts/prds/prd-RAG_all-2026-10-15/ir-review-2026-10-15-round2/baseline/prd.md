## 1. 文档目的与产品目标

RAG_all 是允许用户导入不同领域资料的通用知识库系统，提供 Web 管理与问答界面，以及供业务程序和后续 Agent 调用的 RAG API。用户应能找到资料依据、核验适用条件，在证据不足或互相冲突时得到明确说明。

项目的直接目标是通过实际项目帮助用户深入理解 RAG 运行、技术栈和工程实现，用于求职和面对面面试中的经验讲述，不计划现场演示。用户负责与 AI 核对实现方案、技术栈和项目理解，实际编码、集成、测试与开发问题记录由 AI 承担。预期用约半个月完成本期四场景 RAG，方案核对完成后在 AI 可用额度内推进开发。完成依据是可运行代码、真实改造、可复现测试和评估结果，不以包装材料代替实现，也不承诺求职结果。

用户已确认 Python 为主，首版后端采用 FastAPI＋PostgreSQL＋pgvector，前端采用 Vue 3＋TypeScript＋Vite；选择性抽取 WeKnora、MaxKB 模块并参考设计，组织自己的项目。本轮另授权 John 与 Mary 按四个大问题先 TR、再 TS 收口配套组件、应用边界、生命周期、RAG 和交付方案，具体选择与真实交流见 [技术选择与对话](/E:/aaa-project/rag/_bmad-output/planning-artifacts/prds/prd-RAG_all-2026-10-15/technical-decisions-dialogue.md)。代码抽取、依赖版本、服务接入与实际效果继续验证，本文不将选型或上游能力描述视为本项目已经具备的能力。

文档导入采用已确认的后台任务方案：PostgreSQL 持久化任务状态，独立 Python worker 执行解析、分块和向量化，初始同时处理一份文档；页面显示进度和失败原因，实现失败重试及服务重启后的任务恢复。任务恢复与重复执行的具体机制须在架构和实现中验证，尚不表示相关能力已经完成。

## 2. 使用者与代表性任务

业务岗位描述任务，团队角色描述权限。同一账号可以在不同团队拥有不同角色。

| 使用者 | 要完成的工作 |
| --- | --- |
| 普通员工、新员工 | 找到制度、流程、材料要求与资料中明确的负责人 |
| 客服、技术支持、运维人员 | 根据版本、报错与环境核查可能原因和处理步骤 |
| 售前、产品、研发人员 | 比较文档与版本，逐项核验需求是否有证据 |
| 实施、维修、售后工程师 | 按型号、故障码、表格参数和图示查手册 |
| 知识维护者、领域专家 | 导入、校核、更新资料，排查解析问题并补充知识 |
| 团队负责人 | 管理成员、角色、知识库和维护责任 |
| 应用开发者 | 将检索、问答及结构化证据接入业务程序或后续 Agent |

以下 UJ 为 Mary 设计的代表性任务，四类任务均必须在首版交付。

- **UJ-1 / SC-1：技术支持与故障排查。** 技术支持小林在已登录的团队空间选择有权知识库，提交 v2 升级后连接超时的日志和环境信息。系统返回适用条件、候选原因、按顺序排列的检查步骤和逐步引用。必要版本或环境缺失时先澄清；资料不足以定位根因时明确不确定性，不自动执行命令。
- **UJ-2 / SC-2：企业内部知识查询。** 新员工小周在授权制度库询问出差审批人和材料，得到有版本与出处的流程答案。资料未提供负责人时明确缺失；制度互相冲突时并列展示来源，不自行判定一份制度更有效。
- **UJ-3 / SC-3：多文档对比与能力核验。** 售前小陈选择同一空间内产品 A、B 的授权文档，核验离线部署、审计及批量导入能力。系统按条件逐格给出满足、明确不满足、证据不足或资料冲突，以及版本和引用；未检索到依据不能变成“不支持”。
- **UJ-4 / SC-4：复杂产品手册问答。** 实施工程师小赵查询型号 M2 的 E17 故障、部件位置与参数限制。系统结合正文、规则表格、扫描页及图示说明，保留型号、版本、数值、单位和条件，并定位到页码、表格或图号。型号不明、单位缺失或解析不足时先澄清或限定结论。

## 3. 首版范围与术语

### 3.1 必须交付的范围

- 账号、个人空间、团队协作、知识库授权、平台基础管理。
- 文件上传、解析校核、索引状态、版本替换、删除、失败重试和引用回看。
- 同一空间内授权知识库的检索、问答、多轮追问与多文档对比，覆盖四类场景。
- 用户绑定的只读程序 API、可复现评估和工程交付材料。
- 中文和英文资料；至少两个不同领域的样例资料，其中企业内部样例使用明确标注的模拟或脱敏内容。

### 3.2 首版不交付的范围

- 账号与协作：个人资料分享、普通用户自助注册或任意建团队、独立团队管理员、公开加入链接、申请审批、SSO、邮件与短信接入。
- 资料与检索：文档级权限、跨空间混搜、整库批量导出、回收站。
- 运营与外部集成：计费充值、存储自动迁移、企业系统自动同步。
- 后续 Agent：工具执行、多 Agent、规划、反思和长期记忆等第 1.2 节能力。

首版不要求流式输出，不承诺所有文档结构无损解析或任意复杂原理图自动理解。复杂手册仍须达到 FR-7 与 FR-13 的最低深度；这些限制不构成移除 SC-4。

### 3.3 统一术语

| 术语 | 本文含义 |
| --- | --- |
| 空间 | 资料与会话的访问边界，分个人空间和团队空间 |
| 知识库 | 空间内的资料集合；团队资源授权的最小粒度 |
| 团队角色 | 所有者、知识维护者、知识使用者，决定可执行的动作 |
| 知识库授权 | 指定成员可访问哪些知识库；不能改变团队角色 |
| 负责人 | 可管理该知识库授权和删除整个知识库的人；创建者自动负责，不新增团队角色 |
| 文档版本 | 一次导入或替换的资料内容及关联产物，区分候选、生效和历史版本，用于查询与证据回溯 |
| 候选版本 | 尚未发布的导入或替换结果，不参加查询；达到对应发布条件后才可生效 |
| 生效版本 | 当前用于新查询的版本；首次导入的部分可用版本须同时保留不完整标记 |
| 历史版本 | 被替换的原生效版本，仅供仍有权的历史引用核验，不参加新问答检索 |
| 就绪 | 资料完整处理、索引和程序校核通过，可供查询；与部分可用状态区分 |
| 部分可用 | 首次导入已发布可用部分，失败范围明确、通过内容可定位；查询和引用提示不完整，不用于自动覆盖旧版 |
| 校核 | 格式、产物完整性、来源可回查等程序检查，以及复杂样例的人工对照；程序通过不证明所有文字或事实语义正确 |
| 引用 | 指向文档版本及页码、章节、表格、图号等可核验位置的证据 |
| 程序 API | 供外部程序或后续 Agent 调用的首版只读能力，不等同于 Web 管理功能的全部接口 |
| 程序凭证 | 绑定用户、单一空间、指定知识库及允许动作的有期限密钥 |
| 平台管理员 | 管理账号、团队建立及系统接入与运行资源的独立身份，不自动获得业务资料读取权 |

## 4. 空间、角色与访问规则

| 身份 | 资料范围 | 管理边界 |
| --- | --- | --- |
| 个人空间本人 | 本人的个人资料 | 自行管理；不向其他用户或团队分享 |
| 团队所有者 | 本团队全部知识库，角色本身授予该范围 | 设置、成员与角色、知识库及授权、所有权转让和团队解散 |
| 知识维护者 | 被逐库授权的知识库，以及自己负责的知识库 | 可维护库内所有资料；负责库可管理授权和删除整库；不能管理团队成员或团队角色 |
| 知识使用者 | 被逐库授权的知识库 | 检索、问答、对比、原文与引用查看、单文件下载、问题反馈；不能修改资料 |
| 平台管理员 | 平台身份不授予业务资料读取权 | 建立团队并指定所有者，管理账号、模型、存储、配额和运行状态 |

同一自然人可以兼具平台身份和团队身份，但访问团队资料仍须按其团队权限判定。任何人都不能借平台身份读取他人的个人空间。加入团队本身不授予普通成员任何知识库访问权；所有者的全库范围是该角色的明确能力，不扩散给其他成员。

## 5. 功能需求

FR-1 至 FR-5 沿用原草稿稳定编号，新增需求从 FR-6 连续编号。各条“可检验结果”定义实现验收，不代表已经实现。

### 5.1 空间与团队协作

#### FR-1：个人空间与团队角色

系统支持个人空间和团队空间，用户按当前空间与团队角色操作资源。同一账号在不同团队可拥有不同角色；个人资料仅本人使用。普通用户不能仅凭注册身份创建团队。

可检验结果：同一账号在团队 A 为维护者、团队 B 为使用者时，维护能力分别受对应角色限制；同团队成员、其他团队所有者和仅有平台身份的账号均不能访问其个人资料。普通用户通过界面或管理接口尝试创建团队均被拒绝。

#### FR-2：团队所有者管理

仅平台管理员可创建团队，从有效账号中指定一名初始所有者；每团队始终保持一名有效所有者。所有者可设置团队、向已有有效账号发送带目标角色的站内邀请、撤销未接受邀请、移除成员，以及分配维护者或使用者角色。接受邀请后才成为成员，成员可主动退出。

所有者须先向团队内已有的有效成员转让所有权再退出；原所有者转为维护者，失去所有者固有全库范围，仅保留原有逐库授权与负责库权限。停用所有者账号前必须完成交接，平台管理员可办理所有者变更。转让本身不增加平台资料读取权。

成员退出、被移除或维护者降为使用者时，负责库由所有者接管并保留资料。降级仍保留原逐库访问，但不保留维护及授权管理权。解散团队后停止全部团队资源访问，并进入关联清理。

可检验结果：未接受或已撤销邀请不能进入团队；维护者与使用者不能管理团队成员或分配角色。退出者的团队访问与凭证失效，库内容保留并有有效负责人；转让后旧所有者不能继续访问仅由原所有者身份授予的库。所有者未交接时不能直接退出或被停用。

#### FR-3：授权知识库的维护与使用

所有者和知识维护者可创建知识库，创建者自动负责。团队所有者可管理本团队全部库；其他成员须按库获得授权。库授权决定资料范围，团队角色决定动作，不设单文档权限。

获授权维护者可上传、更新、删除库内资料，包括他人上传的资料，检查解析结果并重新处理；仅库负责人和团队所有者可管理库授权或删除整个库。使用者只能查询、核验、查看原文与引用、下载单个原文件和反馈，不能修改资料。知识库授权不能把使用者提升成维护者。

所有者撤销负责人的该库访问时，同步接管该知识库的负责职责，并清除原负责人的该库全部授权；原负责人不能凭创建者身份恢复访问。所有者固有的全库范围不能通过单库授权撤销，须先转让所有权或按团队生命周期退出。

撤销授权、移除成员、停用账号、删除库或解散团队后，新请求立即受限；检索与完整答案返回前都复核权限。历史会话、引用、下载和追问重新鉴权，不能沿用已经失权的资料。已显示或已下载内容不追溯回收。

可检验结果：维护者创建库后无需另行指定即可管理其授权；能维护另一个授权库的他人资料，却不能仅凭维护权管理该库授权。所有者撤销负责人访问后，该成员不能自行恢复该库权限。撤销后，直接查询、旧会话追问、引用及下载均不能返回失权资料；等待中的答案若涉及失权资料则返回权限变化提示。

### 5.2 平台管理与程序 API

#### FR-4：平台管理与资料访问分离

采用账号密码登录，由平台管理员创建和停用账号，用户可修改本人密码；部署初始化建立首个管理员。平台提供问答模型、向量化模型和可选重排模型的接入配置、验证与可用状态，资料存储配置、验证与占用，以及个人和团队空间的容量、每日问答次数配额管理。

达限时拒绝对应新增操作并说明原因，用户仍可执行权限允许的资料查看与删除等管理操作。影响现有资料的模型或存储变更应提示重处理或迁移需要，不自动执行存储迁移。平台提供任务和依赖运行状态，不提供代登录或全局资料搜索。

已使用的向量配置不可就地覆盖；平台改默认只影响新库或显式重建。每库按不可变配置与活动索引代查询，同次多库不兼容时整请求拒绝并提示需统一索引。首版同维重建按库进行，旧索引继续查询，上传／替换／重处理明确拒绝；删除仍允许并使候选失效，失败、取消和过期必须解除本重建的写入限制，旧任务不能解除新任务限制。切换须覆盖同一活动资料集合，不完整或已变化则不发布。维度变化须显式维护迁移，不承诺任意维度在线切换。

每日问答配额按空间统计，Web 与程序 API 共用。问答及对比在执行能力前原子预留，正常完整答复计一次，包括合规的资料不足、澄清或冲突答复；受理前拒绝、依赖失败、业务超时、答案校验失败和输出前失权不结算，释放预留。同一逻辑操作的重传不重复扣减，显式新操作成功可另计，重放仍复核当前权限。计次归受理时的 Asia/Shanghai 日期，跨日不换日期桶重复计次。纯检索、引用和任务状态读取不扣问答次数；真实外部调用及费用仍逐次记录，产品配额不能替代并发和调用限流。

原件容量以空间内所有保留版本原件字节与在途预留计量，含当前、历史、候选、保留失败候选及清理中原件；界面明确称“原件容量”，不当作全部物理磁盘占用。上传／替换逐文件原子预留，替换不得先抵扣旧版；同内容不同版本分别计，满额不能先删旧版规避双份预算。失败或删除的原件／临时资产实际清完才释放，清理失败继续占用。下调配额不撤销已受理操作，但阻止超额新预留，允许合法查看和删除；派生产物、临时／解包／备份另设物理磁盘保护。

执行问答／对比能力前预留，即使零候选跳过 LLM，由服务器返回合规完整不足答复仍正常计一次。逻辑幂等键独立于诊断 request_id：同键同内容执行中返回状态，成功则重新授权后重放原结果，不新检索／生成／扣次；同键异内容冲突，终态失败只回原失败，过期明确拒绝，不静默当新请求。用户主动重试使用新逻辑键，网络重传保留原键。业务成功以结果、依赖和计次一并持久化为界；之后丢回包不撤销成功，真正业务超时／校验／权限失败才释放。进程中断的预留须有限恢复并隔离迟到执行者，不能永久占用；细节见实施契约。

可检验结果：平台管理员仅凭平台身份查询团队或个人资料被拒绝；已停用账号不能登录，其凭证失效。接入验证失败可识别，超容量不接受新增资料，问答配额耗尽不受理新问答，调整配额按已受理与新预留规则判定。配额时区和计量须在运行配置显示；并发最后一笔预留、跨日重放、同键异输入、操作崩溃、成功丢回包和清理失败均有可重复负例，真实外部调用、Token 和费用逐次记录。

#### FR-5：限定程序调用范围

首版程序凭证绑定用户，只能由用户为本人创建；限定一个本人有权空间、指定知识库与只读动作。有效范围取凭证范围与持有人当前权限的交集。个人空间凭证仅供本人使用，不作为资料分享机制。

Web 与程序请求按入口限定认证渠道；同时携带本应用登录 Cookie 与 Bearer 的受保护请求整体拒绝，不因某种凭据无效、过期或权限更窄而回退另一种。其他无关 Cookie 不视为第二身份。客户端显式选择的空间／库／文档在向量化、检索和生成前逐项检查；任一越界、失权、不存在或不属于所选上级时整请求拒绝，不能静默缩减目标后继续对比。无权和不存在目标对外统一资源不可用，不泄露存在性；后续放行、历史、引用与下载仍再次鉴权。

程序 API 提供检索、同步完整问答、多文档对比、引用读取，以及持有人本人在凭证限定空间与知识库内的导入任务状态查询。返回请求标识、状态、答案或对比结果、结构化引用、文档版本和定位；检索结果与引用不得超出凭证范围。程序 API 不开放资料写入、团队管理或授权管理，Web 仍提供相应的角色受控管理流程。

为网络重传和完整答复恢复，提供持有人本人、原目标及当前凭证范围内的问答操作状态／结果读取；不启动新生成，不扩大只读权限。同键成功重放标明原完成时间和版本，旧源按历史核验规则访问；来源已删除、失权或重放窗口过期时不能返回缓存答案。

密钥仅创建时显示，必须设置有效期，可列出凭证元信息并撤销；持有人可撤销本人凭证，所有者可撤销本团队凭证。账号停用、到期或撤销后失效。

可检验结果：同一用户有权 A、B 两库但凭证仅选 A 时，不能通过检索、对比或引用读取 B；用户失去 A 权限后旧凭证也不能访问。只读凭证不能上传、删除资料或管理成员。错误能区分认证、权限、资源不可用、配额、处理状态及依赖失败，同时不泄露未授权资源内容；接口契约与示例请求纳入交付文档。

### 5.3 资料导入、解析与版本

#### FR-6：文件上传与处理状态

个人本人或团队有权维护者可批量上传 Markdown、TXT、DOCX、文本型 PDF、扫描 PDF，维护标题、所属知识库、文档版本及可选型号、适用条件等元信息。界面显示排队、处理中、待核对、就绪、部分可用（部分失败）或失败，并能查看解析和索引结果；待核对的操作边界见 FR-15。

文件大小、页数、批次数量和空间容量上限由部署配置给出，上传前可见；不承诺任意大小文件。损坏、加密、格式不支持或超限必须明确说明。部分页面失败须列出范围，只使用已通过校核的内容，不把整份资料显示为完整成功。

正常文档通过格式、产物完整性和来源可回查等程序校核后就绪，不要求每份人工审批；程序校核不证明每个 OCR 字符或事实语义正确，复杂样例仍按 FR-7 人工对照。首次导入仅在失败范围明确、通过内容有可靠定位时可发布为部分可用并检索该部分，答案与引用须提示资料不完整；失败范围不明或必要来源缺失时不发布。替换候选的完整性规则见 FR-8。

可检验结果：支持格式的样例均可导入并查询，坏文件与超限文件不会伪装就绪；每个失败或部分失败任务可定位原因与受影响页面，维护者能校核并重试。

#### FR-7：复杂结构解析与校核

解析保留可回查的章节和来源定位：PDF 按物理页从 1 起编号；DOCX、Markdown、TXT 无稳定物理页码时使用章节、块及表图等实际存在的结构位置，不编造页码。规则表格须保留表头、行列关系、数值和单位，并支持简单跨页规则表格；扫描页支持 OCR。图片保留原页或图块、图号、图注及关联正文，并提供可检索的图意说明，允许维护者校核后重新处理。

复杂合并单元格、嵌套表格、复杂原理图不承诺通用自动理解；必须指出受影响页面和限制。仅显示图片不能算完成图示语义任务。用户已选择 MinerU 云端 API 作为文档解析路线；其实际结果须按本条校核，不能因 API 返回成功就认定 OCR、跨页表格或图意已经达标。若需补充图意能力，在样例验证后再核对，不预先承诺某个服务或上游模块直接满足全部要求。

可检验结果：规则及简单跨页表格样例经人工对照后行列、数值、单位一致；扫描样例能够回答标注事实；至少一个必须理解图意才能回答的问题有有效依据。解析缺陷可定位、校核及重新处理，不通过补造数值掩盖失败。

首版校核页提供原件、提取／结构内容、失败范围与位置对照，区分当前生效版、候选和任务；修正限重新上传修订原件、允许的元信息或解析参数形成新候选，不内建通用 OCR／富文本编辑器，不原地改历史来源。PDF 有可信区域则高亮，无区域但有可靠页则页预览并提示；非 PDF 显示实际结构路径、准确提取片段和受控原件下载，不部署 Word 预览服务、不把提取片段冒充原件。定位失效明确报错，缺必需定位的候选不得假装通过。

#### FR-8：资料更新、删除与引用版本

更新以文档版本为单位。新版本就绪前继续使用旧的已生效版本；新版本成功后切换，后续新查询使用新版本，失败不得破坏旧版。历史引用标明原版本；原版本在资料未删除且用户仍有权时可只读核验，但不参加新问答检索。首版不提供已被替换版本的检索选择功能；显式版本对比使用分别导入并标明版本的不同文档，见 FR-12。

不完整的替换候选不得自动覆盖旧版；保留候选供有权维护者校核、修正或重试，达到完整就绪条件且仍是当前待发布候选后再切换。旧任务或旧候选迟到完成不得覆盖更新的有效候选；处理期间被删除的资料不得由迟到任务恢复访问。

删除资料、知识库或团队后先停止对应检索、引用和下载访问，再关联清理原文件、解析产物和索引。有权管理者可见清理中、完成或失败并重试，清理失败不能恢复资料访问。历史引用显示来源已删除。

可检验结果：一次更新失败后旧版仍可查；成功切换后新问答不引用旧版内容。删除后即使清理尚未完成也不可检索或打开原资料；清理重试不会重复生成生效版本。本文“实时检索”仅指索引就绪后用于后续查询，不代表上传立即完成，也不包含自动连接企业系统。

### 5.4 检索问答与四类场景

#### FR-9：授权检索、依据与完整答案

每次检索和问答显式限定一个空间及其中一个或多个有权知识库，可进一步选择文档。系统基于检索证据回答，输出可打开的文档版本与定位，支持同一空间内多文档组合。

目标集合必须显式、非空且无重复；界面“全部有权库”解析为本次实际选择列表。显式目标含无权资源时按 FR-5 整体拒绝，不把被删减的对象伪装为资料不足。

首版采用完整答案一次返回，界面显示等待、成功或失败；设置可见的请求超时配置，不无限等待。证据不足时指出缺失、澄清或限定结论，来源冲突时并列展示。上传资料中的指令不能改变系统规则或授权。模型、解析或检索依赖不可用时返回可识别错误和请求标识，不伪造正常答案。

最终零候选可由服务器确定性返回合规结构化不足，不调用答案模型；这与模型结构／引用校验失败不同，后者整答可见失败、不自动额外付费修正。正常不足仍按 FR-4 计次，纯检索零结果不扣问答。跨文档同一事实冲突须报告双方依据；不能因对比对象各自差异就误标冲突。请求输入、操作重放和安全错误的最小契约见实施契约。

可检验结果：不跨个人／团队或不同团队隐式搜索；答案事实与所引证据一致。无证据、版本不明、冲突和依赖失败各有可复现结果；用户可由引用打开对应版本位置。

#### FR-10：技术支持与故障排查

实现 UJ-1：支持用户提交问题、版本、日志与环境信息，依据适用条件输出候选原因、检查顺序和引用；必要信息不全先澄清。资料只支持候选解释时不宣称已经确定根因。

可检验结果：版本不匹配的处理步骤不被无条件推荐；检查步骤能逐条核验来源。系统不执行建议中的命令，也不声称执行或修复成功。

#### FR-11：企业内部知识查询

实现 UJ-2：回答制度、流程、材料、条件与资料中明确的负责人，注明来源和版本；区分未提供负责人、旧版差异与多份制度冲突。

可检验结果：模拟出差制度样例可得到有依据的流程和材料；未写负责人的资料不生成虚构人名，冲突样例展示冲突和双方证据。样例须标注模拟或脱敏来源。

#### FR-12：多文档对比与能力核验

实现 UJ-3：用户选择授权文档及核验条件，按对象和条件输出对比表。每格具有满足、明确不满足、证据不足或资料冲突之一，并附证据和适用版本。只有直接证据才能认定明确不满足。版本差异对比通过分别导入并显式标记版本的不同文档完成，不检索因版本替换而保留的历史版本。

对比受理有可见可配置上限，初值为文档 2–4 个、条件 1–6 条、单条 256 Unicode 码点、条件文本合计 1024 码点、最多 24 个子检索；这些是未测受理起点，不是质量承诺。空值、重复、越限或越权整体拒绝，不删条件伪装完整。对象／条件使用稳定 ID，每个受理格恰好返回一次；满足／明确不满足至少一个直接证据，冲突至少双方不同证据，不足允许空证据但须缺口说明。v1 每对象为一个所选文档版本，同格冲突来自该版本双方；跨文档同事实冲突仍按 FR-9 报告，原冲突验收不取消。

可检验结果：同一条件在两份产品文档间分别有依据和无依据时，结果分别为满足与证据不足，不把后者标为不支持。对同一条件互相矛盾的来源显示冲突，而非合并成单一确定结论。Web 和程序 API 的状态含义一致。

#### FR-13：复杂产品手册问答

实现 UJ-4：依据型号、版本、故障码和参数条件，组合正文、表格、扫描文本和图意说明，回答步骤、部件、参数及适用限制，定位到页码、表格或图号。

可检验结果：规则表格、简单跨页表格、扫描页及含图意的代表题都能核验；型号混淆、单位缺失或解析不足时不拼接不兼容参数。不能以只支持纯文本问答宣布 SC-4 完成。

#### FR-14：Web 会话、历史与引用回看

Web 提供空间切换、知识库与资料管理、处理结果预览、问答及对比、引用原文、反馈和凭证管理；团队与平台入口遵循角色。会话绑定一个空间，切换空间须新建会话，支持同一空间内追问。

同一会话一次只受理一个未终结生成轮次，使用预期父轮次防止并发和过旧页面混写历史；同逻辑键网络重传不再追加一轮。文档页面分别展示生效版、候选和任务，索引重建另有状态，不能让候选“处理中”遮掉旧版仍可用的事实；关键页面动作与后端权限共用契约。

历史回看和追问重新检查资料权限；涉及已删除或已失权资料的历史回答不得继续展示相关内容，可将受影响回答整体隐藏并提示原因。历史消息不得绕过授权重新进入生成上下文。

可检验结果：有旧会话不等于保留旧权限；撤销后历史、追问及引用均不返回受限资料。普通使用者能完成查询和反馈，不能通过隐藏入口绕过维护或管理限制。

### 5.5 可靠性、观察与反馈

#### FR-15：任务恢复与可识别失败

导入和清理任务在服务重启后必须继续执行或进入明确可重试状态，不永久停留在处理中。重试不能重复产生生效文档版本或重复扣减同一逻辑操作／任务的产品配额；实际外部调用、Token 和费用如实累计。问答业务未完成的中断显示失败，允许显式新操作，不恢复半个答案；已完整持久化成功但回包丢失时按 FR-4 重新授权后重放，不误判为可再次付费生成。

外部解析已发送但结果未知时显示待核对，保留原任务关联，有限自动查询原任务；达到配置核对阈值后显示需处理，不盲目重新提交。当前有维护权限者可继续核对，或在知悉可能重复外部调用及费用后显式重新提交；只读程序 API 仅能查看本人且在凭证范围内的任务状态，不能执行核对或重交。显式重交仍保留原关联，旧结果不得覆盖当前有效候选，不承诺上游请求已取消。期间删除或失权继续按 FR-3、FR-8 阻断访问。

可检验结果：对处理中服务重启、模型断连、解析失败和清理失败分别测试，均能定位任务与原因并采取可见操作。更新失败不破坏旧版，失败重试不重复产生有效资料。

#### FR-16：操作审计、用量与问题反馈

记录账号和团队管理、邀请、角色变化、知识库授权、负责人接管、资料更新删除、所有权转让、配置与凭证变更的操作者、对象、时间、结果和必要错误码。运行记录包含请求或任务标识、各阶段耗时、调用量及可取得的模型用量；问答反馈可标记错误、缺失依据或引用问题。

默认审计与运行日志不记录资料正文、问题及答案全文或密钥。问答历史、原资料与评估原始记录属于受控业务数据，按其空间权限保存，与默认运行日志分开。

停用、成员／角色／所有权、库授权、凭证撤销和资料删除等安全变更同时记录稳定 ID 的最小元数据台账，供独立受控导出与恢复核验，不含正文或秘密。导出区间与缺口必须可见，不能把台账完整性校验误称为已经包含故障前全部安全变更；方法见实施契约。

可检验结果：一次授权撤销、处理失败和问答反馈均可关联到对应对象；普通用户不能读取他人反馈或全局日志。通过日志检查确认不存在原文及密钥泄露；用量统计区分产品配额的幂等计次与每次实际外部调用成本，失败和重试不能从成本报告中消失。

## 7. 评估、成功指标与完成判定

### 7.1 固定样例与统计口径

建立 32 条小规模验收题，四场景各 8 条，其中各 6 条可回答、2 条资料不足，共 24 条可回答与 8 条不足题。可回答题覆盖版本差异、冲突、多文档组合、表格、扫描 OCR 和图意。

首次调优前冻结题目、资料版本、必要证据单元、预期事实与判定规则；另备开发问题用于调优。记录每次运行、全部结果和配置，不能删掉失败题改善成绩。该题集只用于小规模验收，不声称统计泛化或真实企业效果。

必要证据单元是标注的原文片段、表格行列事实或图意事实；一个单元只有被最终候选直接支撑才计命中。最终检索候选上限固定 K=5，不足五条按实际结果评判；基线与改进使用同一匹配规则和上限。

K=5 限制整次请求的最终候选块，不等于必要证据单元最多五个；同一块可直接支撑多个原标注单元，SM-2 分母不因分块改变。多次子检索合并后仍合计最多五块进入生成，不额外塞入邻块、全文或旧回答；裁剪掉的证据不计命中，也不得扩大块来规避上限。对比逐格证据不足需明确标注，但仍须满足原任务通过门槛，不能靠全面拒答达标。

用户已确认检索先完成基础版，再逐步优化，每轮记录真实数据变化作为面试证据。先保留基础向量检索 B0，后续按实际失败提出改动假设，尽量单独调整主要因素；每轮在相同题集与条件下比较 B0、上一轮保留方案和本轮结果，记录配置、每题输出、证据覆盖、任务通过、耗时、资源与调用成本，以及改善、持平、退步和失败。调优使用独立开发题，不能根据冻结验收题反复调参；若发生题目暴露，应记录并另备留出题验证。具体优化手段不在此一次性锁定，逐轮记录统一维护于 [OPTIMIZATION_LOG.md](/E:/aaa-project/rag/OPTIMIZATION_LOG.md)。
