## TR 直接支持与不能外推之处

WeKnora 可借鉴“块有来源身份，索引和引用都回到原块”，不整体移植其所有增强召回。MaxKB 可借鉴“检索、上下文、生成分步并保留段落元信息”，不把 is_active 等同本项目 active_version，也不把其可选授权钩子当所有出口重授权的证明。两项目代码并不能证明本项目 4C4GB、图意、逐格对比或最终五块可达标。[1][2]

pgvector 精确检索保留的是向量距离排序的精确性；它不会保证语义相关，更不会自动提供空间/库权限。过滤必须由后端统一授权给出的范围进入数据库查询。[3] embedding API 的 model 字段与向量维度独立于问答模型命名；选型及输入限制必须读实际使用端点契约。[4]

## TS 门槛、候选与取舍

硬门槛：Q1 显式 Python 步骤/短 Session/统一当前授权；Q2 结构来源、active_version、删除阻断；四场景全部交付；B0 只向量精确检索；最终 K=5；32 冻结题与开发题隔离。偏好顺序：规则一致、可理解、少组件、可逆。没有负载数据，不做虚构数字评分。

| 候选 | 决定与理由 | 代价与重选触发 |
| --- | --- | --- |
| 结构块＋精确向量＋共享受控上下文 | 选为 B0，适配既定 PG，步骤和证据可逐题追踪 | 精确扫描耗时、特定错误码召回与五块覆盖均未知；接入测量 |
| 向量＋关键词/重排 | 作为后续备选，无证据表明首版必须同时安装 | 型号/术语或排序失败有清楚归因时，在开发题隔离比较；不得预先声称改善 |
| ANN | 作为规模/延时触发的备选，不纳入 B0 | 速度与召回取舍和过滤结果须同 K 对照；无容量事实时不提前建立 |
| 参考项目整套 RAG/编排骨架 | 不采用为本项目主骨架；当前只借边界与字段衔接 | 既定显式步骤能覆盖本题；将来复杂恢复/工具编排再论证，不声称框架无用 |

最强反对理由：纯向量可能漏精确术语；比较对象/条件较多时五块很紧。当前选择不掩盖这些风险，直接报告不足与失败，不削减必需事实或调大 K 换通过。最便宜的可逆措施是保持 embedding/检索适配边界、不可变块与版本化配置，后续有证据再改一个主要因素。没有额外服务费用估价；真正 API 调用及索引重建费用实现后累计，不把没有本地模型理解为免费。

## 实施时必须保持的精确定义

### 块与来源

- 一个最终候选是一条已持久化、长度受控、可定位的原始来源块；候选 ID 不等于“整文档聚合包”。一个块可直接支持多个标注证据单元，但不能以虚拟父块、整章或拼接许多来源绕开五块上限。
- 正文保留章节路径与段落；初始约 600 中文字/80 字重叠仅为可调参数，不是论文结论，且最终按选定模型 tokenizer/上限检查。超长句需要安全再拆并保留偏移。
- 表格保留 table_id、表头、行/列含义、单位及条件；按行组切，必要重复表头，跨页行组带多个来源位置。超宽/合并结构不能强行拉平成无列含义文本；标注缺陷并校核。
- 图块证据为已校核的语义说明＋图号/图注及原图位置，可含明确关联正文；缺图意不能仅靠图片存在过关。OCR 文本仍带原页和处理/校核状态。PDF 使用已定 1 起物理页并保存上游基数，DOCX 用结构定位；不重开解析服务选择。
- 所有块带空间、库、文档、doc_version、chunk_config_id、source_locators、校核/完整状态；继承 Q2 ready 后切 active 的发布边界。不完整首次可查内容须展示不完整，不用未通过范围补造答案。

### embedding 与索引版本

embedding_config_id 固定供应商、API/地域、模型名、可观察模型版本、维度、query/document 用途、归一化与距离策略；分块文本前缀规则另有版本。初选文档和查询都显式 L2 归一化、余弦排序，拒绝无穷/NaN/零/维度错误。若供应商 alias 不暴露内部权重版本，记录实际响应 model、调用时间与 request_id，并说明无法完全冻结，不能伪称复现权重。

index_version 在这里指一套块/embedding 配置生成的数据集版本，不意味着 ANN。同次检索只进同一兼容 embedding 配置；多库不一致应拒绝并指出需统一索引。改模型/维度/分块/归一化走候选重建→ready→原子切换；旧向量不混入新查询，保留的原文引用不要求旧向量继续检索。[2][4]

### 检索、五块与上下文

1. 从当前身份、单空间、用户当前库权限求交集；程序 key 再与其库范围/有效性求交。数据库内限定库、文档选择、active_version、未 tombstone、允许查询状态与 index_version，再计算精确余弦距离。不先全库 TopK 后在应用层删越权项。
2. 普通问题一次向量检索；对比从显式选定文档对象及核验条件展开子检索，每路也只用精确向量。子查询数量/文字/耗时/费用完整记录；不通过历史扩大目标对象。按同题追问修正：条件按请求原序、对象按文档 ID 升序组成固定子查询序列；每路内部按余弦距离升序、chunk_id 破同分。固定按名次轮转：依次扫描各路第1名，再各路第2名，跳过已选块，累计五条或耗尽。不比较跨子查询余弦分数；记录查询顺序、名次、选择原因和 merge_config_version，不据冻结题改变配额。此规则不保证逐格覆盖，未覆盖据实不足，SM-1/每场景5/6目标保留，全面拒答不能达标。
3. 开发工具可观察更多库内授权候选及排序，但生成器只看最终五条；每条进入上下文的正文、表头、图意和必要元信息都归属这五条。不得另追加邻块、超额父块/全文、旧答案、隐形多轮生成证据。每次请求仅最终一次受该集合约束的答案生成；未来若多次子生成也不得绕开全请求集合。
4. 只有最终五条**实际传给模型的片段**直接支持的标注原文/行列/图意单元才计覆盖；若受 token 预算裁剪掉关键支持，不计命中。优先丢弃整块或重新形成受控片段并留痕，不让展示候选和生成实见内容不一致。
5. 多条件多对象对比逐格找证据；不支持与没搜到区分；冲突至少标双方来源。五块不能覆盖全部格时保留不足，不能偷换成完整能力清单。冻结题若达不到验收仍记录失败，不为提高分数反复换题或降低事实要求。
6. 资料指令不能覆盖系统规则。生成输出使用本轮 evidence_id 白名单，结构检查无效 ID/版本/状态，但这不等于自动证明语义真。首版只允许去 JSON 围栏和空白等不改变语义的本地规范化，不自动追加模型修正调用；仍不合 schema 或 ID 越界时整答返回 ANSWER_VALIDATION_FAILED 及 request_id，不展示草稿、不静默删引用伪装成功。用户重试算新请求，全部真实调用、失败、重试累计用量费用。后端保存 evidence_id→空间/库/版本/块/定位映射，resolve 引用时重新授权；正文、原件、图像和下载均经过同一服务，不信模型 URL。

### 历史与放行

会话绑定空间；历史记录保留全部生成依赖集合。有限历史仅用于经授权的语义消解/改写，默认最终生成不接收旧答案正文。任何历史依赖失权或删除均可整答隐藏，不能让用户仅靠“继续上一条”复活旧内容。改写文字及新查询不改变当前空间/库/文档约束，输出不把历史作为证据。

沿用 Q1 在检索、上下文前、完整答案放行前用新鲜短 Session 读当前授权；模型等待期间不持 DB 事务。当前 key 到期/撤销、用户失效、资料删除或范围变化均阻断；若上下文版本在此期间已不再 active，本次结果按来源状态变更失败，不把旧版混进新的答案。历史引用仍可在未删除且有权时回看旧版。最终检查不是撤权事务与物理网络发送的全局原子操作，不承诺召回已显示内容。

## 评估记录与停止理由

- 32 题四场景各 6 可答/2 不足；冻结题目、资料版本、必要证据单元、预期事实、判定规则，独立开发题调优。四场景不缩减，手册须覆盖表格、简单跨页、OCR 和至少真正图意题。
- 每次留最终五块与实见上下文、结构输出、人工判定、阶段耗时、资源峰值、每次 API 请求/模型/用量/实际费用来源。B0、上一保留轮和本轮同条件比较；失败/重试的调用不能丢。默认运行日志不存全文；受控评估原始记录按空间权限保存。
- SM-1：24 题至少 21 且每场景≥5/6；SM-2：24 题必要证据单元覆盖≥85%；SM-3：引用支撑≥95%、定位打开100%；SM-4：8 不足题全部正确；SM-5：表格/OCR/图意/冲突/版本差异关键题各过。所有目标均未实测，不能用全部拒答或少写事实投机。
- 独立 SM-6 权限负例另列分母，包含跨空间/团队/未授权库、key 缩权/撤销、tombstone、旧版不参加新检索、历史/追问/引用/下载及输出前撤权；质量分不能抵消越权。成本缺计价只报调用量；样本不足20不报有代表性的 P95。
- 未知：API 型号/实际维度/版本可观察性、块与子检索初值、图意结果、B0效果、目标机耗时/内存/价格账单均需后续接入。不把这些技术验证转成用户问题。user_only_missing=无。
